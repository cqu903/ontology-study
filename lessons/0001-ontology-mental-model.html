Lesson 0001 · 约 10 分钟

Ontology 心智模型：不是数据库，也不是语义层

金融/保险案例 · 配套速查：核心概念速查表

为什么从这一课开始

你要做的决策是「是否在数仓、业务系统、AI Agent 之上自建统一本体层」。这个决策里最危险的词是"本体层"——它在行业里被混用于指数据库 schema、指标语义层、知识图谱。概念不清，后面的架构权衡全是空中楼阁。所以第一课只做一件事：把 Ontology 到底是什么、不是什么钉死。

官方定义

The Ontology is an operational layer for the organization. … a digital twin，把组织已整合的数字资产（数据集、模型）映射为它们所代表的现实业务概念。 — Ontology Overview · 官方文档
拆解 · 两类元素

语义元素（对象 / 属性 / 链接）回答：业务世界里有什么？
动力学元素（行动 / 函数）回答：能对它做什么、怎么算？

只有语义元素的，叫语义层。两类齐备、且行动能写回源系统的，才是 Palantir 意义上的 Ontology。

五分法：拆解任何业务场景

构件一句话金融示例
对象 Object现实实体或事件的建模单元客户、账户、保单、交易流水
属性 Property对象的特征值保额、风险等级
链接 Link对象间的关系（一等公民，不是运行时 join）投保人—持有—保单
行动 Action一次性提交的一组变更，写回源系统冻结账户、批准理赔
函数 Function以对象/对象集为输入输出的业务逻辑欺诈评分

精确定义见速查表 · 五大构件。

它坐在数据之上，但不是数据

官方文档给了一个直白的对照：dataset → object type，row → object，column → property，join → link type（Core Concepts）。本体层是加在数据资产上的一层映射绑定——它不要求新建数据库，也不规定坐在数仓上。

回应你的直觉

你在确立学习目标时说："本体论没有规定和数据仓库强绑定。"这是对的。对象的底层数据可以是批数据集、流、虚拟表或直连数据源；一个对象类型甚至可绑定多个源。本体层由它的角色定义（为人和 Agent 提供统一的语义 + 操作契约），不由底下的存储定义——数仓只是可选宿主之一。这个立场会成为你自建架构的基石，第 3 课专门展开。

练习：六道分类题

每道题给出一个你业务里的场景，判断它最应建模为五分法中的哪一类。第 5 题有陷阱——答错比答对学到更多。

本课带走的一句话

心智模型

Ontology = 业务的语义层（对象/属性/链接）+ 操作层（行动/函数），它是对既有数据资产的映射绑定而非新的数据库，供人类应用与 AI Agent 统一读写。少了操作层，你建的就只是语义层。
