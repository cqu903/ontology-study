Palantir Ontology 核心概念速查

全部定义取自 Palantir 官方文档 · 打印友好 · 课程统一以此为准

一句话定义

The Ontology is an operational layer for the organization … a digital twin that maps datasets and models to the concepts they represent. — Palantir Foundry Docs · Ontology Overview

拆开看，它由两类元素构成：

元素类别包含回答的问题
语义元素 semantic 对象、属性、链接 业务世界里有什么？
动力学元素 kinetic 行动、函数、动态权限 能对它做什么、怎么计算？

五大构件

构件官方定义（意译）金融/保险示例
对象类型 Object Type 现实世界实体或事件的 schema 定义；单个实例称 object，实例集合称 object set 客户、账户、保单、理赔案件、交易流水
属性 Property 实体或事件某项特征的 schema 定义；具体实例上的值称 property value。可跨对象类型共享（shared property） 保额、风险等级（可被账户/保单/贷款共用）
链接类型 Link Type 两个对象类型之间关系的 schema 定义；单个关系实例称 link 投保人—持有—保单；账户—转入—交易
行动类型 Action Type 一组对对象、属性值、链接的变更/编辑的 schema 定义，可由用户一次性提交，并可触发副作用（写回源系统） 冻结账户、批准理赔、调整授信额度
函数 Function 一段代码逻辑，接收输入返回输出；原生支持以对象/对象集合为输入、读属性值，可被行动与应用复用 欺诈评分、集中度计算、定价模型调用

另有 接口 Interface（描述对象类型的形状与能力，实现跨类型多态）与 Roles（本体资源的统一权限模型），进入落地设计时再展开。

数据 → 本体 的映射类比

官方文档给出的对照（这是理解"本体层是对数据资产的绑定"的关键）：

数据世界本体世界
dataset（数据集）object type（对象类型）
row（行）object（对象实例）
column（列）property（属性）
field value（字段值）property value（属性值）
join（连接）link type（链接类型）

出处：Core Concepts · Docs

本体层不绑定数据仓库

对象的底层数据（backing data）可以来自多种资产：批数据集、流式数据、虚拟表、直连数据源，甚至一个对象类型绑定多个数据源（multi-datasource object type）。本体层由它的角色定义——为人和 AI 提供统一的业务语义与操作契约——而不是由"坐在哪个存储之上"定义。数仓只是可选的宿主之一。

参考：Ontology Architecture · Docs

语义层 vs Ontology

维度传统语义层 / 指标层Palantir Ontology
角色查询/指标的只读抽象组织的操作层（operational layer）
实体逻辑视图、指标定义有类型、有关系、可编辑的对象
行动不支持一等公民——Action 写回源系统
消费方BI / 分析分析 + 运营应用 + AI Agent

面向 AI 的关键词：OAG

Ontology-Augmented Generation：让 LLM/Agent 的推理落在结构化、实时的运营数据与可执行的行动上，而不只是检索文档（RAG）。学术表述称其为 "an enterprise superset of RAG"（MDPI Electronics 2025）。
